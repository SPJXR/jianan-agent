## 线上缺陷修复记录（2026-09-21）：检索排序倒置导致库内问题被误答「未找到」

> 背景：2026-09-20 部署至公网服务器（8.137.11.193）后测试反馈：A 组第 1/3/4/9 题「没有生成答案」，C/D 组全部走兜底，B 组（库外题）兜底正确。

**现象与定位**：以 A 组题「特种作业人员报名考核需要满足什么条件？」为例，线上返回 `backend=llm` 的 36 字「未找到」回答——**不是检索兜底路径，而是 LLM 生成环节放弃**。本地复现发现检索命中 8 条（3 文档），但排序错误：无关文档 0069（cov 0.50）排在正确文档 0063/0064（cov 0.88）之前。

**根因**（app/retrieval.py 旧打分公式）：
1. bm25 bonus `1/(1+|rank|)` **方向倒置**——FTS 匹配越强（|rank| 越大）bonus 越趋近 0，而 LIKE 泛词召回块（无 rank）拿满分 1.0；
2. 标题加权对含泛词（作业/人员）的无关文档同样生效，无法纠偏。

两者叠加 → LLM 收到的前 4 条来源全部无关 → 按提示词第 3 条「片段与问题不直接相关即输出未找到」保守拒绝。B 组（真库外题）拒绝正确属巧合性正确；C/D 组为同根因 + top_cov 低于阈值的兜底路径。

**修复**：
- `app/retrieval.py`：bm25 bonus 改为归一化 `|rank|/max|rank|`（匹配越强分越高）；LIKE 召回块固定弱 bonus 0.25。
- `app/llm.py`：系统提示词第 3 条改为「片段按相关度排序但靠前也可能无关，须先通读全部片段；任一片段相关必须作答」；第 4 条明确「仅当所有片段均无关才输出未找到」。

**验证**：
| 项 | 结果 |
|----|------|
| 失败题检索排序 | ✅ top 变为 0064（cov 0.88），11 道测试题（含 6 示例题）全部 top 命中正确文档且 top_cov ≥ 0.25 |
| 失败题真实 LLM 全链路（重启后） | ✅ `backend=llm, 327 字`，正确引用 0064 年龄/学历/体检/安全记录条款 |
| 示例问题回归 | ✅ 有限空间气体检测题正常（336 字，引用 0070） |

**部署**：`deploy-pkg/jianan-app.tar.gz` 已按同结构重打包（仅 `app/retrieval.py`、`app/llm.py` 内容变化，其余与线上版本逐字节一致）。服务器最小化更新：替换这两个文件并重启服务即可，`.env` 不变。

**遗留**：A/C/D 组完整题目清单未获取，修复后需测试组回归原题集确认；口语化表述（C/D 组）若仍有个别低于 0.25 阈值，属迭代 3 混合检索升级范围。

## 第二轮线上缺陷修复（2026-09-21）：多轮检索稀释 + 口语化词汇鸿沟

> 背景：V2 上线后测试组复测（`docs/上线测试问题集.md`）反馈：A4/A9 仍无答案、C1 无联想、C3/C4 无答案，其余通过。

**根因 1：F6 检索改写稀释（A4/A9）**
旧实现把上一问拼进 query 参与覆盖率计算：`query = question + " " + last_user`。按序号连问时，上一问的词摊薄相关度——A9「开工流程」被上一问「震后专家队」带偏，top 变成 0003（无关）；C4 直接降为 0 命中。
**修复**：`retrieval.search(question, k, context_query)` —— 上下文词**只用于扩召回**，覆盖率只按当前问题的词计算。

**根因 2：过滤顺序错误（连带发现）**
旧代码先按分数截断 top-k、再过滤低覆盖率，导致扩召回引入的高分无关块（bm25/标题加分高但覆盖率 0）占满 8 个名额，真正相关的块被挤出后被过滤 → 命中数归零。
**修复**：先按覆盖率（≥0.2）过滤，再排序截断。

**根因 3：LIKE 合并查询截断（连带发现）**
`text LIKE '%桩头%' OR '%施工%' OR ... LIMIT 120` 中泛词填满结果集，罕见词（桩头）的块被挤出候选。
**修复**：逐词 LIKE 查询（每词 LIMIT 60），保证罕见词必然进入候选。

**根因 4：口语化词汇鸿沟（C1/C3/C4）**
「挖坑底下干活」vs「有限空间」、「房子/震完」vs「房屋/震后」、「着火」vs「阻燃」——BM25 字面匹配无法跨越。
**修复**：两阶段检索。新增 `config.REWRITE_MIN_COVERAGE=0.5`，弱命中时先由 LLM 把口语问题改写为法规术语（`llm.rewrite_query`，非流式 8s 超时，失败沿用原结果），再检索一次并择优采纳；前端新增 `rewriting` 状态提示「命中较弱，正在换一种说法重新检索」。仅弱命中路径付出额外一次小查询代价。

**验证**：
| 项 | 结果 |
|----|------|
| A4 连问（后接 A3） | ✅ 192 字，命中 0072「桩头直接凿除法」禁用/限制条款 |
| A9 连问（后接 A8） | ✅ 484 字，命中 0067 开工一件事流程（线上/线下两种途径） |
| C1 挖坑干活 | ✅ 触发改写，611 字，命中 0069 有限空间（中毒/窒息/爆炸/淹溺 + 先通风再检测后作业） |

| C4 密目网着火 | ⚠️ 改写后命中 0072 非阻燃密目网禁用条款，但模型判定知识库无「着火后处置措施」并附说明——属合理拒绝，建议题集预期改为「命中禁用条款即可」 |

## 2026-10-11 逐字契约复验（AC1.2 在新索引上重新执行）


输出：`tests/verbatim_check.txt`（人读报告）与 `tests/verbatim_check.json`（机器可读，供回归断言引用）。

**校验口径**（三级，从严到宽，任一级命中即视为逐字一致）：

| 口径 | 含义 |
|---|---|
| strict | 片段文本是 `kb/text/<doc_id>.txt` 原文的**完全原样**子串 |
| no_page | 去掉源文本中的 `【第N页】` 分页标记后为子串 |
| collapsed_ws | 两侧折叠全部空白后为子串（排版换行/空格差异不算改写，中文无需空格） |

**复验结果（2026-10-11，索引 414 片段）**：

| 项 | 数值 |
|---|---|
| 片段总数 | **414** |
| 逐字命中 | **414** |
| 不一致 | **0** |
| 其中 strict（完全原样） | 201 |
