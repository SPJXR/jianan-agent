# ADR-001：埋点上报通道选型（自建内存计数端点）

- 状态：已接受（Accepted）
- 日期：2026-09-20
- 决策人：开发 Agent（依据 HANDOFF §五.2.1「上报通道（需架构决策）」授权范围）
- 关联：docs/PRD.md §11、docs/SPEC-ITER2.md §2、docs/HANDOFF-后续开发计划.md

## 背景与上下文

PRD §11 要求 9 个必埋事件可测量（激活率/核心价值交付率等 §12 指标的前提），上报通道在 HANDOFF 中列为待决策项，候选：

1. 自建 `POST /api/open` 类计数端点（服务端只存计数）
2. Umami 类自托管/第三方统计方案
3. 仅本地控制台开关（现状，不可测量）

## 决策

**采用自建轻量计数端点**：前端 `trackEvent` 统一封装 → `navigator.sendBeacon("/api/track")` 批量上报 → 服务端 `app/track.py` 白名单清洗后仅做内存计数（事件名 → 当日次数），`GET /api/track/stats` 查询。本地调试保留 `window.__TRACK_DEBUG__` 控制台开关。

## 理由

- **合规优先**：PRD §11 明确不采集 PII、不上报 IP 明文与问题原文。自建端点可将「只存计数、不落盘」作为代码级硬约束；第三方方案引入数据出境/合规审查成本，与产品"本地知识库、可信"定位冲突。
- **零依赖零成本**：不新增外部服务与费用，公网发布时随应用一同上线；Umami 需额外部署与运维。
- **sendBeacon 适配弱网**：工地弱网场景下 beacon 不阻塞主流程，页面关闭也能发出。
- **精度取舍已知**：内存计数重启清零，仅能看当日趋势，不做长期留存。当前阶段目标只是"指标第一次可测量"，长期统计待公网运营后按数据再决策（见 OPEN-DECISIONS）。

## 后果

- 正面：激活率、核心价值交付率、错误率当日可查；无第三方依赖与合规风险。
- 负面/已知边界：计数不持久化（重启清零）；无用户级漏斗明细；stats 端点公网后需考虑加口令（迭代4 触发条件）。
- 缓解：F8 反馈与问答记录存浏览器本地可导出，人工抽检流程不依赖服务端明细。

## 遵循

- `app/track.py`（白名单清洗 + 内存计数 + 独立限流 60/min）
- `web/app.js` trackEvent SDK（公共属性 + 脱敏）
- SPEC-ITER2 §2 契约与 AC-T1~T9 验收标准

## 增补（2026-10-11）：计数改为持久化，采集范围不变

**变更**：`app/track.py` 的当日计数由「纯内存、重启清零」改为「SQLite 持久化」，落盘于 `data/track.sqlite`，表结构 `track_counts(day, event, n)`；`GET /api/track/stats` 增加 `?history=1` 返回最近 30 天逐日汇总。

**原因**：原「重启清零」的取舍前提是"当前阶段目标只是指标第一次可测量"（见上文「精度取舍已知」）。进入参赛材料阶段后，需要可核查、可回溯的运营数据，重启即丢失使数据不足以支撑"实施/应用成效"的举证，因此按本 ADR 原计划中"长期统计待公网运营后按数据再决策"的路径推进到持久化。

**没有改变的**（这是本次变更的边界，必须显式声明）：

- **采集范围一字未增**：仍然只存「日期 + 事件名 + 计数」三元组。**不存问题原文、不存用户身份、不存 IP 明文、不存属性明细。**
  客户端即便在事件里带上 `question` 字段，`_sanitize_event` 之后的属性也**只用于校验、不进入存储**——该行为由 `track_persistence_report.txt` 的落盘文件原文探测验证（向落盘文件写入探针字符串后确认其不存在）。
- 事件名白名单正则、单请求最多 20 条、限流 60/min 全部保留。
- 落盘失败时自动退回内存模式，绝不影响问答主链路；`stats` 响应新增 `persistent` 字段暴露当前是否处于持久化状态。
- 持久化文件放在独立的 `data/track.sqlite`，**不与 `kb/kb.sqlite` 同库**——后者会随 `tools/build_kb.py` 重建，混放会让运营计数随重建丢失。

**已知遗留（原「负面/已知边界」第 3 条仍未处理）**：`/api/track/stats` 公网可访问且无鉴权。现在数据可跨日留存，暴露面比内存态略大（仅统计量，无明细）。原 ADR 记为「迭代4 触发条件」，本次未一并处理；**公网部署时建议加 `TRACK_STATS_TOKEN` 校验或仅内网可达**。

**验证**：`python _verify_track.py`（项目上级目录）→ 上报 → 重启服务 → 计数保留 PASS、落盘文件无问题原文 PASS。
