# ADR-002：混合检索采用条件补充方案（bge-small-zh-v1.5）

- 状态：已接受（Accepted）
- 日期：2026-09-22
- 决策人：开发 Agent（POC 数据驱动；用户在计划问答中确认「双模型 POC 数据说话」+「向量检索+双路融合」范围）
- 关联：docs/research/POC-混合检索对比.md（完整数据）、docs/decisions/OPEN-DECISIONS.md 第一在决项、docs/research/论文精读-LoRA+RAG领域问答-车蕾2026.md（方向 A）
- 计划偏离：原计划 RRF（k=60 各取 top10）；POC 证明朴素 RRF 与加权融合均劣化，改为条件补充（见理由）

## 背景与上下文

V3 检索层为 jieba + FTS5 trigram BM25 单路 + 覆盖率重排 + 两阶段 LLM 改写，口语化问题部分解决但字面匹配存在天花板（qa_regression 中 C1 未命中）。指导老师建议参考车蕾论文引入 Bge 向量检索。OPEN-DECISIONS 第一在决项要求 POC 定稿：bge-small 本地推理 vs 云端 embedding API vs 仅调优 BM25。

## 决策

**bge-small-zh-v1.5 向量检索 + 条件补充融合**：

- 线上模型 bge-small-zh-v1.5（512 维，ONNX int8 量化部署，服务器 CPU 推理）
- 强命中（max coverage ≥ 0.5）：完全走 BM25 原排序，向量路不参与
- 弱命中（max coverage < 0.5，原改写重检场景）：向量 top-5 置前 + BM25 top-3 追加
- 兜底判据维持 BM25 覆盖率主判据；HYBRID=off 开关可秒级降级回 BM25 单路

## 理由（数据见 POC 报告）

- **模型选型**：VEC-small 单路 top-1 78.6% / top-3 100% / MRR 0.893，全面优于基线（71.4% / 85.7% / 0.792）；bge-large top-1 仅 57.1%，小语料（422 片段）垂直场景下 large 反而引入噪声，且体积 14 倍、CPU 编码更慢。云端 embedding API 未进入实测：本地 small 已达标且零额外延迟与费用。
- **否决均匀融合**：RRF(small) top-1 降至 64.3%、加权网格（VEC_W 0~8）全部 64.3%，均低于基线——BM25 已调优的全序被均匀融合「平均」掉，强命中精确条款题被拖累。
- **否决向量阈值兜底**：库内 top1 相似度 min=0.493 与库外 max=0.605 重叠，单一向量阈值不可分；B 组兜底实际依赖生成层诚实作答，维持现状。
- **条件补充验证**：top-1 78.6% / top-3 100% / MRR 0.881，与向量单路持平；强命中 11 题与 BM25 逐题一致（零回归）；C1 由弱命中向量路救回。该方案以 0.012 MRR 的代价换取强命中场景的完全确定性。

## 后果

- 正面：口语题召回突破（top-3 100%）；精确查询零回归风险；HYBRID 开关保证可回滚；bge-small CPU 编码约 5ms，P95 延迟预算内。
- 负面/已知边界：融合规则引入分支复杂度（强/弱命中两路径，回归测试需覆盖两分支）；向量索引随语料更新需重建（build_vec_index.py 纳入 kb 重建流程）；库外误召回未消除（依赖生成层兜底，B 组行为与 V3 一致）；MRR 相比向量单路损失 0.012（C3 OK@1→OK@2）。
- 下一轮候选：Bce-reranker 神经重排（待双路融合线上收益明确后评估）。

## 增补（2026-11-05）：兜底判据与向量路的实现脱节修复（上下文改进计划 2.4）

### 被违背的契约

本 ADR 决策段明确写着「**兜底判据维持 BM25 覆盖率主判据**」。但 `main.py` 在
上下文装配后用 `top_cov = max(primary 块的 coverage)` **无条件重算**兜底判据——
这行代码诞生于版本库建立时（f73f8f4，纯 BM25 时代，primary 块 coverage 即判据，
重算无害）；本 ADR 引入向量路后未跟着改。向量块 `coverage=0.0` 是
`vector_search.py` 的设计（「覆盖率是 BM25 判据，向量块不参与」），于是弱命中
路径上出现实现与契约的脱节。

### 实测复现（PM-02，跨 414/509 两版 KB 稳定失败）

问「特种作业人员的资格证书快到期了，怎么办理延续？」：

1. 原问题弱命中 top_cov=0.45 → 走向量路，fused 5 块**全部是向量块**
   （0064 第 14~18 条延期复核——语义检索捞回了完美答案块），coverage 全 0；
2. 改写词「特种作业人员 资格证书 延期 复审 办理」重检 top2=0.45 **恰好相等**，
   `top2 > top_cov` 不成立 → ADR-007 并集合并不触发；
3. L168 重算 `top_cov = max(0×5) = 0` → 低于 MIN_COVERAGE → 误走「未找到」兜底。

用户侧表现为：**引用卡片展示着延期复核条款原文，答案却说「知识库中未找到
直接相关的条款」**——自相矛盾。C1 当年能被救回，只因其改写词覆盖率高
（top2=0.67 > 0.45）触发了合并，BM25 版本块（coverage 0.67）胜出掩盖了这个 bug。

### 决策：兜底判据取两路较大值（一行修复）

```python
top_cov = max(top_cov, max((h["coverage"] for h in primary), default=0.0))
```

`hybrid_search` 返回的 `top_cov` 本来就是 BM25 主判据（改写路径含
`max(top_cov, top2)`）；primary 重算值只可能覆盖它、不可能修正它。取较大值后：

- 强命中题：两值相等，**零变化**；
- 弱命中 + 改写合并（C1 类）：两值相等，**零变化**；
- 弱命中 + 向量独占（PM-02 类）：恢复 BM25 判据 0.45 ≥ 0.25，不再误兜底；
- BM25 无命中：`hybrid_search` 返回空（向量不救零命中），兜底不变，**库外防线不动**。

### 验证

- `tests/iter6_fallback_test.py` 3/3：PM-02 backend=llm 且答案含 30 个工作日/
  延期复核/3 年；C1 合并路径回归；库外弱命中题拒答防线（契约规则 1/4 生效）。
- 62 题全量 A/B（本机 509 块 KB，基线 = 3.3 落地后的 `ctx-validity-v3`）：
  见 `docs/eval/2.4改写词对齐实测结论-20261105.md`。
- 护栏：validity_ctx_test 9/9、qa_regression 14/14、MT 组 6/6（MT-02 单次抖动，
  复测 3/3 过）。

### 顺带否决：计划原方案「检索关键词进 user 消息」

改进计划 2.4 原设想在 user 消息加「（检索关键词：有限空间作业）」帮 LLM 跨
词汇鸿沟。实测 PM-02 修复后，deepseek 拿到口语问题「快到期了怎么办理延续」+
正确向量块，**自主完成「延续→延期复核」语义桥接**，答案关键词全命中；C 组
口语题本就全过。与 2.1/2.2 POC 否决同纪律：**无实测复现的失败不引入提示词改动**，
本增补即 2.4 的实际产出。
