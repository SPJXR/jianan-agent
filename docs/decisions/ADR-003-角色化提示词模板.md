# ADR-003：角色化提示词模板（4 类角色 + 默认通用）

- 状态：已接受（Accepted）
- 日期：2026-09-23
- 决策人：开发 Agent（依据论文精读 §方向B 与 PRD 用户画像；用户指令「开工B方向升级」）
- 关联：docs/research/论文精读-LoRA+RAG领域问答-车蕾2026.md（模块④）、docs/PRD.md（用户画像）、ADR-002（检索层边界）、tests/iter5_role_test.py
- 计划对照：按论文模块④的「角色设定 + 指令说明 + 输出风格」三要素落地；论文的 %field% 结构化变量（按行业细分）在本项目无对应维度，不引入

## 背景与上下文

V4 生成层使用单一系统提示词，所有用户同款。论文实验表明角色化模板在同类场景最高 +10.5pp 余弦相似度，且无需训练。PRD 用户画像恰有 4 类角色（安全员/项目经理/监理/编辑政务），可直接映射。项目现状：检索层刚完成 ADR-002 混合检索升级并上线，稳定性优先。

## 决策

**新增 `app/prompts.py` 作为角色模板唯一真相源，角色只作用于生成层：**

- 5 套模板：default（通用）/ safety（安全员·现场检查）/ pm（项目经理·合规责任）/ supervisor（监理工程师·审查验收）/ gov（政务编辑·条文溯源）
- 每套模板 = 开场角色设定句 + 契约规则 1~6（**逐字不变**）+ 第 7 条角色输出侧重
- **default 模板与 V4 现网系统提示词逐字节一致**（回归红线，tests T4 断言）
- API：`/api/chat` 请求体新增可选 `role` 字段，非法/缺省一律回退 default（旧客户端零影响）；`done` 事件回显 `role`；新增 `GET /api/roles` 供前端动态渲染
- 前端：输入区上方「回答视角」选择条（/api/roles 拉取，localStorage `jz_role_v1` 记住，接口失败整条隐藏不影响问答）
- 埋点：`question_sent` 增加 role 属性；新增 `role_changed` 事件（走既有标量白名单清洗）

## 理由

- **生成层隔离**：检索层（ADR-002 条件补充方案）刚上线稳定，角色不触碰检索可保证零回归——qa_regression 14/14 与 iter4 9/9 在改动后原样通过即为证据。
- **契约规则逐字复用**：逐字引用、诚实拒答、越界拒答是 PRD 产品生命线（AC1.2），任何角色化不得改写。模板把规则 1~6 原文内嵌，角色诉求只通过 persona 与第 7 条表达；iter5 测试对 6 条关键句逐句断言。
- **宽松回退而非 400**：role 校验失败回退 default 而非报错，保持 SSE 契约向后兼容（老版本前端/脚本不带 role 字段行为与 V4 完全一致）。
- **前端动态拉取而非硬编码**：角色清单以后端为唯一真相源，调模板无需改前端。

## 后果

- 正面：同一问题可按角色获得不同侧重（实测「桩头凿除」default 182 字 vs pm 353 字，pm 版含替代工艺与条款定位）；无训练成本；可随时加角色（改 prompts.py 一个字典）。
- 负面/已知边界：角色差异依赖模型遵循度，无硬保证（temperature 0.2 下观察稳定）；评测集尚未按角色分组，角色收益暂无量化指标（待评测集扩充到 50+ 题时补）。
- 回滚：前端隐藏 roleBar + 后端忽略 role 即回到 V4 行为；default 模板逐字节未变，单角色风险可控。
