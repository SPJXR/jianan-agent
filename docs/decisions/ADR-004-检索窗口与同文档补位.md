# ADR-004: 检索评分窗口扩到 14 + 同文档补位装配 LLM 上下文

## Status: Accepted (2026-09-23)

## Background

评测集 v2（62 题）线上试测暴露 3 题答「未找到」，但答案原文均在库内：

| 题号 | 问题 | 答案块实际排名 | 挤掉它的噪音 |
|------|------|----------------|--------------|
| DEF-04 | 有限空间氧气浓度合格值 | 11（0070 表2 块） | 同文档安全装备/检测条款（cov 同为 0.83，BM25 bonus 更高） |
| DEF-08 | 震后评估结论标识颜色 | 13（0012 附件3 块） | 表单碎片；top-8 内的第十二块只有「标识参考格式见附件3」的指针 |
| PM-06 | 消防设计审查特殊建设工程 | 9（0065 说明-一块） | 0065/0066 申请表复选框行（含「消防设计审查」「特殊建设工程」字样，FTS bonus 高） |

文档级 hit@8 = 55/55，失败全部是「对的文档、错的块」：答案块排在 9~13 位，被
`RETRIEVAL_TOP_K=8` 的上下文窗口切掉，LLM 看不到答案原文。SAF-10 复测正常
（答案块排 1，同块含起重吊装+脚手架两张表），首次空响应为网络抖动。

## Decision

1. 新增 `config.RECALL_WINDOW = 14`（可环境变量覆盖）：检索评分/排序窗口从 8 扩到 14。
2. `_chat_stream` 上下文装配改为两级：top-8 为主证据，9~14 位中**与主证据同文档**的块
   补进上下文（≤6 条），限制噪音规模。
3. 「未找到」兜底门槛（MIN_COVERAGE）仍按 top-8 主证据的最大覆盖率判定——库外题
   （B1~B5）兜底行为与 v5 逐字节一致。
4. LLM 改写触发与比较沿用 hybrid_search 返回的窗口级 top_cov，两路口径一致。

## Consequences

- 正面：DEF-04/DEF-08/PM-06 答案块进入上下文，本地端到端实测三题全部答出
  （引用编号 [10][11][13] 正是补位块）；62 题评测集检索指标 hit@3 不变（53/55）。
- 正面：不改 BM25/向量打分公式，ADR-002 的 POC 结论不受影响。
- 负面：上下文从 8 条扩到 8~14 条，token 成本上升；同文档补位可能引入少量
  低相关片段（由 LLM 契约规则约束「只依据片段作答」缓解）。
- 负面：改写触发条件从 top-8 口径变为窗口口径（极少数 top-8 弱、9~14 位强的
  问题不再触发改写）；实测 C 组口语题行为不变。
