# ADR-006：法规时效的检索侧降权（草案/已废止不得作为第一依据）

- 状态：已接受（Accepted）
- 日期：2026-10-11
- 关联：ADR-002（条件补充混合检索）、ADR-005（表格感知分块）、`docs/PRD.md §11`、`kb/docs_meta.json`

## 背景与问题

2026-10-11 用真实问题做端到端验证时发现：问"有限空间作业前需要检测哪些气体"，**首条引用来自 0070《房屋市政工程有限空间识别及施工安全作业指南（征求意见稿）》**。

征求意见稿不是生效规范。在一个面向安全员现场决策的工具里，把草案排在第一位作为依据，属于内容准确性缺陷；而该工具的核心承诺恰恰是"每条结论可溯源、不可编造"。

根因分两层：

1. **数据层**：`kb/docs_meta.json` 中 34 份文档的 `valid_status` 全部为空（DB 默认 `unknown`），检索层无法区分正式稿、试行稿与征求意见稿。
2. **算法层**：`hybrid_search` 的弱命中分支把向量 top-k **直接置于结果前列**（`fused = list(vec_hits)`），该分支完全不查看文档时效；BM25 主路径也没有任何时效因子。

## 决策

1. **检索层引入时效乘性降权**，系数集中在 `retrieval.VALIDITY_PENALTY`：
   - `repealed` → ×0.35
   - `draft` → ×0.60
   - **`unknown` / `effective` / 空值 → ×1.0（一律不降权）**
2. **降权位置在所有加分项之后**（覆盖率、bm25 bonus、整句命中、标题命中都算完再乘），保证它是纯粹的"依据资格"调整，不与相关性信号相互缠绕。
3. **向量路单独补一道稳定分区** `_validity_partition()`：向量命中仍置前，但已核定为草案/已废止的被整体压到末尾，其余相对次序不变。这是必要的——只在 `search()` 里降权挡不住向量路。
4. **降权不是过滤**：草案与已废止条款仍可被检索到、仍会展示，只是不占第一依据位。
5. **引用契约新增 `validStatus` 字段**，前端在**引用来源卡片**与**知识库来源抽屉**两处用同一套徽章口径（`validityBadge()`）显示"现行有效／已废止／试行·征求意见稿／时效待确认"。

## 关键取舍：为什么 `unknown` 不降权

这是本决策最重要的一条，也是最容易被"顺手改严"的一条。

当前 34 份文档**全部**是 `unknown`。若把 `unknown` 也纳入降权：

- 等于让"还没核定"直接变成"检索质量下降"，所有排序同时塌陷重排，**ADR-002 用 POC 实验换来的"强命中零回归"结论当场失效**；
- 且会给出错误激励——为了让指标好看而草率填写时效状态。

因此本决策要求：**时效处理只在文档被明确核定为草案或已废止时生效**；未核定的走原排序，并在界面上如实显示"时效待确认"。数据层的空白由核查工作（回填 `valid_status`）解决，不由算法层掩盖。

## 后果

- 正面：草案/已废止不再充当第一依据；用户与评审都能在界面上直接看到依据的时效状态；核查工作与算法行为解耦，可分别推进。
- 已知边界：**降权系数 0.35 / 0.60 是经验值，未经真实双盲评测标定**。目前只保证"方向正确 + 不改变未核定语料的排序"，不宣称数值最优。待 34 份时效状态回填完成后，应结合分层问题集重新评估是否需要调参或改为硬性重排。
- 待办：`kb/docs_meta.json` 的 `valid_status` 与 `version_date` 仍待逐份核定（**优先 0069 与 0070**，二者是同一指南的试行版与征求意见稿）。

## 遵循

- `app/retrieval.py`：`VALIDITY_PENALTY` / `_validity_factor()` / `_validity_partition()`；`SQL_CAND` 与 LIKE 召回 SELECT 增列 `d.valid_status`
- `app/vector_search.py`：`top_k()` 的 SELECT 增列 `d.valid_status`
- `app/main.py`：`_sources_payload()` 增加 `validStatus`

## 增补（2026-10-11）：拆分 `trial` 与 `consultation`，并完成首批核定

### 修正的建模缺陷

本 ADR 初稿把 `draft` 定义为"征求意见稿/试行"，前端标签也写作"试行/征求意见稿"。**这是错的**——二者法律效力相反：

- **试行**：已印发、正在施行，只是带试行性质 → 完全可以作为依据；
- **征求意见稿**：尚未生效 → 根本不能作为依据。

把二者合并，要么把有效的试行稿错误降权，要么把未生效的征求意见稿放过。而本项目最要紧的一对文档 **0069（试行）与 0070（征求意见稿）恰好是同一指南的两个版本**，合并标签会让系统在最该区分的地方失去判断力。

### 变更后的词表与系数

| `valid_status` | 含义 | 系数 | 界面徽章 |
|---|---|---|---|
| `effective` | 现行有效 | 1.0 | 现行有效 |
| `trial` | 试行，已印发施行 | **1.0（不降权）** | 试行·现行有效 |
| `consultation` | 征求意见稿，未生效 | **0.15** | 征求意见稿·未生效（标红） |
| `repealed` | 已废止 | 0.35 | 已废止（标红） |
| `na` | 附件表格/示例/报名表/征订单/讲话稿等，无独立时效属性 | 1.0 | 附件·无独立时效 |
| `unknown` | 待确认 | **1.0（不降权）** | 时效待确认 |

初稿的 `draft: 0.60` 取消。`unknown` 不降权的原则不变（理由见上文"关键取舍"）。

### 首批核定结果

由 `tools/backfill_validity.py` 写入 `kb/docs_meta.json`，逐条依据与来源见 **`docs/法规时效核查台账.md`**：

| 状态 | 份数 | 文档 |
|---|---|---|
| `effective` | 5 | 0011（建质〔2016〕253号）、0012、0063、0064（住建部令第60号，2026-06-01 施行）、0072（公告2024年第186号，2025-08-03 实施） |
| `trial` | 4 | 0069（2025-06-23 印发试行）、0071（建办质〔2024〕63号）、0073（建办质〔2024〕56号）、0074（建办质〔2024〕43号附件） |
| `consultation` | 1 | **0070**（征求意见稿，已由 0069 取代） |
| `na` | 13 | 0002、0004、0026、0030、0049、0052、0053、0057、0062、0065、0066、0067、0068 |
| `unknown` | 11 | 0001、0003、0005、0006、0017、0029、0048、0050、0051、0075、0076 |

**核定纪律**：只有拿到文号/公告号或印发日期等硬证据的才写具体状态；拿不到的一律留 `unknown` 并在界面显示"时效待确认"，**不猜**。13 份 `na` 是按文档类型判定（表格、报名表、征订单、示例、讲话稿），不需要外部证据。

### 修复验证

原缺陷："有限空间作业前需要检测哪些气体"的首条引用是 **0070 征求意见稿**。

核定后同一问题的 top-5 依据全部为 **0069 试行版**，0070 掉出前 5（实际连 BM25 top-8 也未进入）。由 `tests/validity_test.py::TestDemotionTakesEffect::test_live_index_no_longer_leads_with_draft` 长期守卫。

### 索引重建的零内容变更证明

`tools/build_kb.py` 重建后：`chunks` 表仍为 **414 行**，`SHA-256(chunk_id, doc_id, seq, clause, pages, text)` 仍为 `2e65efd1315806ff…`，与重建前及 `tests/chunks_snapshot.json` **逐字节一致**——即时效核定只改 `docs` 表元数据，未触碰任何引用片段文本。`tools/verify_verbatim.py` 复跑仍为 414/414 逐字命中。

### 用例前提的连带修正

`tests/iter2_api_test.py` 原有一条 `check("V1 缺省全部为待确认(unknown)", all_unknown)`，描述的是回填前状态，核定后必然失败。按"改断言不删断言"的原则替换为三条：取值必须在词表内、`unknown` 份数须少于全部文档（证明核定已启动）、征求意见稿须恰好 1 份并已标出。

`tests/validity_test.py` 中原依赖"全库无降权文档"的两个用例改为**在临时库副本上自造基线**（先把全部文档重置为 `unknown` 再改目标文档），使断言与真实核定进度解耦，后续继续回填时不会再失效。
