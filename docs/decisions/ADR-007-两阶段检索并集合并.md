# ADR-007：两阶段检索的改写结果按并集合并（改写只能加分，不能翻盘）

- 状态：已接受（Accepted）
- 日期：2026-10-12
- 关联：ADR-002（条件补充混合检索）、ADR-004（检索窗口与同文档补位）、迭代3（口语化问题改写）、`app/main.py` 两阶段检索段、`tests/iter3_rewrite_test.py`

## 背景与问题

2026-10-11 起，`tools/verify_all.py` 的「迭代3 口语改写」一项开始在同一份代码上交替给出 `8/8` 与 `7/8`：

```
FAIL C1 回答命中预期文档 0069  | docs=['0017', '0017', '0017', '0017']   ← 一次
PASS C1 回答命中预期文档 0069  | docs=['0069', '0017', '0017', '0017']   ← 另一次
```

C1 是口语题「工地上挖坑底下干活有啥危险要注意的？」，走的是弱命中 → LLM 改写 → 二次检索这条路。

用一次性探针把改写文本和两路检索结果同时打出来，根因很清楚（探针已删，数据如下）：

| 改写输出 | 改写路 top_cov | 改写路 top-5 文档 |
|---|---|---|
| `基坑作业 有限空间作业 危险 安全注意事项` | 0.500 | 0017 ×5 |
| `基坑作业 有限空间作业 危险因素 安全注意事项` | 0.640 | 0069, 0017 ×4 |

原句检索稳定（top_cov 0.330，`0071/0071/0071/0069/0057`，**0069 本来就在第 4 位**）。翻转只由一个词的差异引起：**「危险」还是「危险因素」**。

而当时的合并策略是整份替换：

```python
if top2 > top_cov:
    hits, top_cov = hits2, top2      # 改写路只要分数高一点，原路全部作废
```

于是改写多认出一个词、或少认出一个词，就能把原句已经捞到的 0069 彻底丢掉，五条引用全换成 0017。**同一道用户问题会得到两份不同依据**——这对一个把"可溯源"当核心承诺的工具是实质缺陷，不只是测试抖动。

## 决策

**弱命中路径改为并集合并：两路结果按 `chunk_id` 去重、同一块取较高分，再按分数降序排。**

```python
if top2 > top_cov:
    merged = {h["chunk_id"]: h for h in hits}
    for h in hits2:
        cur = merged.get(h["chunk_id"])
        if cur is None or h["score"] > cur["score"]:
            merged[h["chunk_id"]] = h
    hits = sorted(merged.values(), key=lambda h: h["score"], reverse=True)
    top_cov = max(top_cov, top2)
```

配套两点：

1. **改写调用的 `temperature` 由 0.1 降到 0.0。** 查询改写要的是最可能的规范术语串，不是创作，贪心解码是正解。但它**只降低翻转频率、不消除翻转**——DeepSeek 服务端本身仍非确定，实测同一题仍会在两种改写间跳。所以本 ADR 的重点是检索侧不能假设改写稳定，而不是把温度调成 0 就当问题解决了。生成侧仍用可配置的 `LLM_TEMPERATURE`。
2. **C1 的断言由单解改双解**：接受 0069《房屋市政工程有限空间识别及施工安全作业指南（试行）》**或** 0017《工程项目施工人员安全指导手册》。

## 为什么不改产品去迁就"必须命中 0069"

0017 命中的块标题是「（一）土方作业主要有哪些注意事项」——对「挖坑底下干活有啥危险要注意」来说，它就是正确出处，甚至比 0069（有限空间，面向受限空间而非一般坑槽）更贴题。

所以原来的断言不是"产品错了"，而是**把一个多解题写死成了单解题**。按"改断言、不删断言"的纪律处理：

- 保留 `回答命中预期文档` 这一项（仍然要求检索真的捞到相关法规，不接受空手）；
- 保留 `回答非空且 done 正常`（未动）；
- 只把可接受的 `doc_id` 前缀从 1 个放宽到 2 个，并在 CASES 里写明为什么两个都对。

放宽断言和为了变绿而放宽断言是两件事，区别在于这里有一份文档标题作为独立证据，且改完之后 3 次连跑 `8/8`、全量总校验 `9 PASS / 0 FAIL / 2 SKIPPED`。

## 影响面与不变量

- **只在弱命中路径生效**：`if (not hits or top_cov < REWRITE_MIN_COVERAGE)` 才进这个分支，强命中题（含 14 题检索回归的全部题）一行都不经过，ADR-002 的"零回归"性质不受影响。
- 并集只会让候选**变多**，不会让原本在 top-16 里的块消失；ADR-004 的 `top-8 主证据 + 同文档补位 ≤6` 契约与 `RECALL_WINDOW=16` 均未改动。
- 跨查询比分：`top2 > top_cov` 这个判据本来就在跨查询比较 coverage，本决策沿用同一前提，没有引入新的可比性假设。

## 复现与验证

- `python tests/iter3_rewrite_test.py`（需服务在 :9000）连跑 3 次：`8/8`、`8/8`、`8/8`（改动前为 `7/8`/`8/8` 交替）。
- `python tools/verify_all.py`：`9 PASS / 0 FAIL / 2 SKIPPED`，两处 SKIPPED 是公网实例不可达与早期脚本无判定行，均非本次改动引入。
