# ADR-008：口语同义映射表作为 LLM 改写的前置快路径

- 状态：已实施（2026-10-24）
- 背景/驱动：路线图 B-1「口语同义映射表」——「挖坑→有限空间」这类口语→术语映射目前
  完全依赖弱命中时的一次 LLM 改写调用（8 秒超时窗口、非零失败率、每题多付一次费用）。
- 相关决策：ADR-007（两阶段检索并集合并——改写只能加分不能翻盘）、
  ADR-002（条件补充混合检索——弱命中向量置前）。

## 语境

两阶段检索（迭代3）解决了口语题「挖坑底下干活」类问题，但代价是：弱命中题必然
多一次 LLM 调用（首字延迟 +约 1~8s）。对高频固定搭配（词表可枚举的口语词），
这次调用是可省的。

##决策

### 采纳：外置映射表 + 召回侧扩展（`app/synonyms.py` + `kb/synonyms.json`）

1. **只扩召回，不进覆盖率分母**：命中映射的目标词追加进 recall terms（与
   `context_query` 同一纪律），覆盖率仍按原问题的词计算——防止映射词把无关块
   相关度虚高、误触发强命中路径。
2. **词表外置**：`kb/synonyms.json` 人工维护，与 `app/llm.py` 改写提示词的示例词
   保持同一套（当前 13 键），保证快路径与慢路径行为一致。
3. **快路径不替代慢路径**：映射未命中的口语仍走 LLM 改写（映射表是改写的前置
   缓存，不是替代品）；命中映射后若仍弱命中，改写照常触发。
4. **零侵入降级**：文件缺失/JSON 损坏 → `expand()` 返回空列表，主链路不受影响。

### 否决的备选

- **把映射词拼进覆盖率计算**：会让「规范术语题」因映射词误命中而虚高相关度，
  且污染 ADR-002 强命中零回归的口径。
- **硬编码进检索代码**：词表演进需要改代码，违背「配置外置」纪律。
- **只扩映射、砍掉 LLM 改写**：词表覆盖不了未枚举口语（如「震完了房子咋评估」
  的组合变体），改写仍是必要兜底。

## 后果

- 正面：高频口语题省一次 LLM 调用（首字延迟下降）；词表命中即生效、无网络依赖。
- 负面/风险：词表是人工维护面，坏映射（错误目标词）会扩出噪音召回——
  由「覆盖率分母不含映射词」与三重护栏（qa14 → iter4 → 62 题全量）兜底；
  词表新增条目必须过护栏后入库。
- 验证：`tests/synonyms_test.py` 单元用例（6/6）+ 三重护栏 + 62 题全量
  （对比 temp-0.2 基线，见 `docs/ACCEPTANCE.md` B 档节）。
