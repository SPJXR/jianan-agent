# ADR-010：多轮改写利用——指代解析进检索改写路

- 状态：已实施（2026-10-24）
- 背景/驱动：路线图 B-2「多轮改写利用」——`rewrite_query(question, history)` 只传
  上一问，多轮对话里「那第三条呢」「检测的频次呢」这类指代无法解析，弱命中改写
  拿到的上下文不足。
- 相关决策：迭代3 两阶段检索（弱命中才改写）、ADR-007（改写并集只能加分）。

## 语境

生成侧（`stream_chat`）本就把完整 history 传给 LLM；缺口只在**检索侧改写**：
旧提示词只附「对话上一问」，指代词（那/它/第X条）悬空，改写产物仍是残缺查询。

## 决策

### 采纳：改写提示词带三轮上下文 + 指代解析规则

`app/llm.py rewrite_query`：
1. 附**最近 2 个用户问题 + 最后一条助手回答摘录（150 字）**（`_clean_history`
   已保证入参合法：≤6 条、assistant ≤500 字）。
2. 系统提示词新增规则 3：含指代时必须结合历史解析为明确对象，输出**完整独立查询**
   （示例：「那检测的频次」+ 历史谈有限空间 → 「有限空间作业 气体检测 频次」）；
   历史与当前问题无关时忽略历史。
3. 无 history 的调用路径提示词**逐字节不变**（C 组口语题单轮场景零影响）。

### 否决的备选

- **把多轮历史拼进首查 context_query**：context_query 只带上一问是 2026-09-21
  线上反馈的定论（历史词稀释相关度致误兜底），不动。
- **改写整份替换首查结果**：ADR-007 已否决（改写只能加分不能翻盘），本决策不变更。

## 后果

- 验证：新增独立多轮评测组 `docs/eval/eval_set_mt.json`（5 事实题 + 1 拒答题，
  关键词组逐条对照语料原文核对）+ `run_eval.py --set` 支持。首跑 **mt-v1：事实题
  5/5 全绿（ret3/ctx_hit/answer_full_cov/citation 全 100%）、拒答 1/1**
  （`docs/eval/results/eval_mt-v1_20261024.json`）。
- 62 题主集零影响：主集无 history 字段，请求体与旧版逐字节一致。
- 风险：改写提示词变长（+~150 字）——改写本就是 8 秒超时的非关键路径，
  失败即沿用原结果，风险可控。
