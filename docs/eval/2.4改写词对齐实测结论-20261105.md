# 2.4 改写词对齐 · 实测结论报告

> 执行：2026-11-05（上下文改进计划第 2 期第 4 项，第 2 期收官）｜本地实例 `127.0.0.1:9001`（37 份 / 509 块）
> 结论：**调研发现真问题不在「LLM 不知道改写词」，而在兜底判据与向量路的实现脱节；一行修复恢复 ADR-002 契约，PM-02 跨双 KB 稳定失败修复；计划原方案（关键词进 user 消息）实测否决**

---

## 一、计划假设 vs 实测发现

计划原问题定义：「检索用改写术语、LLM 只见原口语问题」的映射鸿沟；原方案：
user 消息加一行「（检索关键词：有限空间作业）」。

实测三步否定/修正了该假设：

1. **C 组口语题（C1/C3/C4）本机基线全部通过**——LLM 跨词汇鸿沟没有造成可量化失败；
2. 62 题失败归因显示，口语类失败（PM-02）的链路**根本没走到 LLM**：答案文本是
   `no_answer` 兜底模板；
3. 完整链路实测（PM-02「特种作业人员的资格证书快到期了，怎么办理延续？」）：

| 步骤 | 实测数据 |
|---|---|
| 原问题检索 | 弱命中 top_cov=0.45 → 向量路，fused 5 块**全为向量块**（0064 第14~18条延期复核，语义检索捞回完美答案），coverage 全 0 |
| LLM 改写 | 「特种作业人员 资格证书 延期 复审 办理」→ 重检 top2=**0.45 恰好相等** → `top2 > top_cov` 不成立 → ADR-007 并集合并不触发 |
| 兜底判定 | `main.py` L168 用 primary 块 coverage 重算 → max(0×5)=**0** → 低于 MIN_COVERAGE=0.25 → 误走「未找到」 |

用户侧表现：**引用卡片展示着延期复核条款原文，答案却说「未找到直接相关的条款」**——
自相矛盾。PM-02 在线上 414 块与本机 509 块双 KB 均稳定失败（非 0080 排序扰动）。

**根因定性**：L168 诞生于纯 BM25 时代（f73f8f4），ADR-002 引入向量路（向量块
coverage=0 为设计）后未跟着改——**实现偏离了 ADR-002 契约「兜底判据维持 BM25
覆盖率主判据」**。C1 当年能被救回，只因改写词覆盖率 0.67>0.45 触发合并、
BM25 版本块胜出，恰好掩盖了 bug。

## 二、改动（一行 + 注释，app/main.py）

```python
top_cov = max(top_cov, max((h["coverage"] for h in primary), default=0.0))
```

兜底判据取「hybrid_search 返回的 BM25 主判据（含改写路径 max）」与「primary 块
重算值」的较大者。分路径影响分析（实测全部验证）：

| 路径 | 两值关系 | 行为 |
|---|---|---|
| 强命中 | 相等 | **零变化** |
| 弱命中+改写合并（C1 类） | 相等 | **零变化** |
| 弱命中+向量独占（PM-02 类） | 0.45 vs 0 | 恢复 BM25 判据，不再误兜底 |
| BM25 无命中 | hits 空 | 兜底不变，**库外防线不动** |

## 四、计划原方案否决（与 2.1/2.2 POC 同纪律）

「检索关键词进 user 消息」不落地，证据：

1. C 组口语题基线全过（无失败可修）；
2. PM-02 修复后 LLM 拿到口语问题「快到期了怎么办理延续」+ 正确向量块，
   **自主完成「延续→延期复核」语义桥接**，无任何提示词辅助；
3. 真问题（兜底判据脱节）发生在 LLM 调用之前，提示词方案帮不上。
