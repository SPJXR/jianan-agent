# 3.1 相邻条款定向注入 · 实测报告（2026-11-07）

## 一、计划假设与调研修正

计划（改进计划 v2 第 3.1 项）原设想：**top-3 主证据**若被分块切断，注入相邻块补全。

调研实测推翻了「按位次」的触发设计：

1. **目标案例不在 top-3**：PM-06（特殊建设工程消防设计审查情形）的答案断裂块是 0065 清单
   前段（seq=17，块尾「…集体宿舍；」），在检索窗口排第 9、补位区——top-3 规则覆盖不到。
2. **全库断裂率仅 10%**（51/509 块块尾为 `，、；：`）：按**断裂信号**触发天然窄面，
   预算可控（注入上限 3 块），比按位次更准。
3. **next 块去重**：next 已在上下文内则不重复注入。

## 二、实现

- `app/main.py`：上下文装配后扫描 `context_hits`，块尾 ∈ {`，`,`、`,`；`,`：`} 的块经
  `retrieval.get_chunk_context` 取 next 块全文挂 `adjacent_next`，上限 3 块。
- `app/llm.py build_context`：片段尾部追加逐字 next 全文 + 显式标注
  `〔接本片段之后的相邻条款，供衔接；引用此部分内容时仍标注编号 [N]〕`。
- **幻觉红线**：相邻块不进 sources 编号体系（`_sources_payload` 固定字段挑选取值，
  不透出 `adjacent_next`），引用卡片无对应块，引用归源块编号。
- **prev 不注入**：中文法规「下文承接上文」语义向前，前文缺失可由锚点+词面召回兜住，无实证收益。
- 零标注零注入路径输出与历史版本逐字节一致（单测守卫）。

### 开发中踩到的中间 bug

首版端到端验证 PM-06 仍无「一类高层」：`main.py` 调 `llm.stream_chat(sources,…)` 时
`_sources_payload` 重建 dict 把 `adjacent_next` 丢掉了——注入挂在 hits 上但没透传到
LLM 上下文。修法：调 LLM 处单独合并该字段（SSE 对外契约不变）。

非 3.1 引入。记录为跨日对比口径注意事项。

## 六、诚实的收益面评估（专测组未强行凑题）

探测多组「问后半内容」问法（楼梯破坏情形/围护墙/作业分类等）发现：**问句词面命中
next 块时 next 直接被召回**（本来就能答），注入不改变结果。3.1 的真实收益面是
**「问整体清单、答案条目在列举后半」的 PM-06 型窄场景**（全库约 10% 块存在断裂，
其中仅部分构成该场景）。按评测纪律不为凑专测组而造题——跨块专测以 PM-06 变体
固化进 `eval_set_v2.json` 注释，不再单设新组。
