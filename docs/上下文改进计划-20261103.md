## 一、现状诊断：上下文构建的完整链路（实测代码）

```
用户问题 + 最近3轮历史（前端截500字）
        │
        ├─ 检索：hybrid_search(问题, 窗口16, 上一问扩召回)      [覆盖率只按当前问题]
        ├─ 弱命中 → LLM改写（含指代解析）→ 重检 → 并集合并       [ADR-007：改写只加分]
        │
        ├─ 上下文装配：top-8 主证据 + 同文档补位≤6 = 最多14块    [main.py 迭代6]
        │
        └─ 生成：system(角色+契约) + 3轮历史全量 + user(14块片段+原问题)
                [llm.py stream_chat]
```

**关键实测事实**（写死在代码注释与 ADR 里的踩坑记录）：

| # | 事实 | 证据 |
|---|---|---|
| 1 | 16 条全量装配时 deepseek 对长上下文中排后的答案块**拒答**（DEF-04 复现两次）——靠截回 14 条缓解，治标 | main.py L154-158 注释 |
| 2 | PM-06 上下文覆盖率 0.75：答案块排在补位窗口边界（supp[6] 恰在截断线） | A-1 报告 + main.py 注释 |
| 3 | 3 轮历史**无相关性筛选**全量进 messages，与当前问题无关的历史同样占用上下文 | llm.py L167-169 |
| 4 | 相邻条款（prev/next）只进前端引用卡片，**不进生成上下文**——跨块语义衔接靠锚点硬扛 | main.py L326 仅卡片用 |
| 5 | 上下文装配按"块数"截断（14 块），**不看 token 长度**——块长度差异大，实际 token 数不可控 | main.py L158-167 |
| 6 | 进上下文的块**是否被答案引用**没有任何度量——上下文利用率是盲区 | run_eval.py 无此指标 |

**一句话诊断**：检索侧已到 100%（A-1 实测），瓶颈整体移到**上下文的组装、长度控制与利用效率**——这正是老师说的"上下文问题"。

## 二、改进计划（四期，评测先行）

### 第 1 期 · 先建度量（没有度量就没有改进）【本周，1 天】

| 项 | 内容 | 产出 |
|---|---|---|
| 1.1 | **run_eval 新增三个上下文指标**：① `ctx_hit`（预期块进上下文判定，落地遗留 R1）② `cite_util`（答案实际引用的 [n] 编号数 / 上下文块数——利用率）③ `cite_pos`（被引用块在上下文中的位次分布——检验"中段沉底"） | run_eval.py 扩展 + 62 题基线跑一遍，出首份《上下文利用率基线报告》 |
| 1.2 | OPEN-DECISIONS 落条：上下文改进立项（本期各子项作为待决子项登记） | 登记册追加 |

> 这一步不改任何产品行为，纯加度量。先知道 14 块里平均几块被引用、被引用的块排在第几位，后面的每项优化才有对照数字。

### 第 2 期 · 生成上下文优化【1~2 周，逐项过护栏】

| 项 | 问题 | 方案 | 验证口径 |
|---|---|---|---|
| 2.1 上下文重排序 | "lost in the middle"：中后段块被 LLM 忽略（事实 1） | **U 型排序**：最相关块放头部、次相关垫尾、中等块放中段；或最相关 top-3 前置 + 其余保序 | DEF-04/PM-06/SAF-07 三题专测 + 62 题全量；cite_pos 指标应向头部集中 |
| 2.2 上下文 token 预算化 | 块数截断不看长度（事实 5） | 统一字符预算（如 6000 字）：块数 × 单块截断联动，低分块截 300 字、主证据保全文 | answer_full_cov 不降 + 拒答率不升 |
| 2.3 历史相关性筛选 | 无关历史占上下文（事实 3） | 规则版先行：只送"与当前问题有词面重叠的轮次 + 最近 1 轮"；LLM 版进阶：复用改写器做历史压缩（每轮压成一行结论） | 新增多轮指代评测组 5 题（"那第三条呢"类），既有 62 题不回归 |
| 2.4 改写词对齐 | 检索用改写术语、LLM 只见原口语问题 | user 消息加一行："（检索关键词：有限空间作业）"——让 LLM 知道片段与问题的映射，降低跨词汇鸿沟的理解成本 | 弱命中题组（C 组口语题）专测 |

### 第 3 期 · 结构增强【2~4 周】

| 项 | 问题 | 方案 | 验证口径 |
|---|---|---|---|
| 3.1 相邻条款定向注入 | 跨块语义断裂（事实 4） | 仅对 top-3 主证据注入 next 块（续表/续条场景），显式标注"[相邻条款，供衔接]"，预算单独计 | 新增跨块评测组（表格跨页题 3~5 道）；幻觉红线：引用编号只能指向主证据 |
| 3.2 角色切换历史标注 | 切角色后历史语境错位 | 历史消息加"（当时角色：安全员）"前缀，或切换时前端提示 | iter5 角色契约测试 15 项不回归 |
| 3.3 时效状态进上下文 | 片段文本无时效标注，LLM 可能引用已废止条款原文 | 片段头加一行"〔状态：征求意见稿，未生效〕"——ADR-006 的降权在检索侧，这里是生成侧对齐 | 0070 征求意见稿类题专测；防"把未生效当现行" |

### 第 4 期 · 研究向（与图增强方向合流）【学期内】

| 项 | 内容 |
|---|---|
| 4.1 文档图上下文 | 台账里已有"母通知-附件"文号关系（如 0069/0070 同指南两版本）。建文档关系图，检索命中附件时自动带出母通知的时效与层级——既是产品功能又是图增强预训练研究的落地场景，**与大创/论文方向互喂** |
| 4.2 长上下文策略消融 | 第 2 期各方案（U 型排序/预算截断/历史压缩）做成可配置开关跑消融——这套实验本身可以写进论文（检索增强 × 上下文工程联合优化） |

## 四、给组会的口径

- 老师点的"上下文问题"经实测定位为：**检索已满分（55/55），瓶颈在上下文组装与利用**——长上下文中段沉底、无相关性筛选的历史、无 token 预算、无利用率度量。
- 应对策略是**评测先行**：先加三个上下文指标拿到基线数字，再逐项优化逐项验证，不盲改。
- 第 4 期与图增强研究对齐，产品迭代与论文实验共用同一套消融设施。
