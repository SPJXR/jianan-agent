落在 `提交物/00_官方文件/抽取文本/ocr补读/`。第一次读到本赛项自己的条款，其中四条此前不在我们的检查清单里：

## 二、一句没有实物支撑的声明：`labelsSource`

三份随包材料对"62 题是谁出的"给了三种说法：

| 位置 | 原话 |
|---|---|
| `07_AI工具使用补充说明.pdf` | 评测集题目与标准答案**学生依据条款原文自行标注**，列在"未保留 AI 生成内容"下 |
| 作品包 `docs/eval/评测集-v2-角色化62题.md` | **出题人：WorkBuddy**（迭代 6 前置工作） |
| `05/材料清单目录` 证据分级 D 行 | 部分评测题由 AI 辅助生成，**`labelsSource=synthetic` 标记保留** |

去数实物：`docs/eval/eval_set_v2.json` 62 题、只有 9 个字段
（id / group / role / type / question / expected_docs / clause / key_points / keywords），
`docs/eval/results/*.json` 十个结果文件里也没有 `labelsSource` 或 `synthetic`。
**这个字段从来没被实现过**，而仓库 README 还写着"eval/ 目录含 labelsSource 标记"。

三分歧里"标记保留"这一份是硬伤：它主张一个不存在的证据存在。
加上第一、二份互相打脸，而按上面第 4 条赛程，做原创性审核的正是校内。

作者口径确认后统一为一句：**题目文本初稿由 AI 起草，62 题全部经参赛学生逐题筛选、修订后定稿；
期望文档与标准答案要点由学生对照条款原文标注；评测集不设 AI／人工分类标记。**
据此改了五处（07、作品介绍文档 4.4 局限条、评测集 md 头部、仓库 README、材料清单目录 D 行），
并留一条常驻检查：**随包件里 `labelsSource` 只允许以"从未实现／不设"的否定式出现**，命中即红。

两份内部规划件（冲刺清单、视频脚本）当时也按"这个标记存在"写过话。它们是过程记录，
原文不回改，各追加一条 2026-10-22 的更正注记说明该字段从未实现。
已封存的 AI+教育 版目录常量同样保留原样。

顺手复核：演示视频成片里没有"合成样本"这类说法——按帧 OCR 扫过 288 帧（233 帧有可读字幕），
`合成`、`synthetic` 均 0 命中，所以这条不影响已交付内容。

## 三、匿名闸的词表漏了开发者自己的用户名

包内身份词表只有校名、6 个真名和一个手机号，报"0 命中"。
把扫描范围放宽到嵌套作品包内的 `.txt` 运行输出后，扫出 **6 个文件**带着
`C:\Users\30832\…`（开发机用户名）与 `WorkBuddy` 路径痕迹，集中在 `tests/` 下几个
`*_out.txt`、`retrieval_test*.txt`、`pip_pywin32.txt`——都是当时抓的原始运行输出。

不一致的地方在于：同一个开发机用户名，我在《异机核验记录》里专门掩掉并反查过，却在另一条通道原样发了出去。
处理方向：这类 scratch 输出既不是可运行系统的组成部分，也不是证据（测试脚本 `.py` 和《系统核验报告》才是），
应从作品包排除，同时把用户名加进闸的词表——**词表要从"我在别处掩过什么"反推，而不是只列显眼的姓名**。

## 四、这一页留下的教训

- 凡是"从 PDF 抽文本再核对"的流程，第一步要断言**每页抽到的字数大于阈值**；
  抽到 0 字必须显式报"这一页没读到"，不能让 8 字节的空壳冒充已读。
- 凡是主张"某标记／某字段／某文件已保留"的句子，落字前去实物里 grep 那个名字，
  数不出来就把句子降级成"我未做该标记"。
- 同一对象在两份材料里出现两种说法时，先假设自己错，回一手数据源裁定，不要挑一份顺眼的抄。
