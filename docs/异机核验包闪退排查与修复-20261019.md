## 一、结论：四个缺陷，其中三个在"我们这边"

同学的机器没有 Python 环境这一先验假设是错的——真正的原因有三条出在交付包里：

| # | 缺陷 | 现象与机理 | 修法 | 复测 |
|---|---|---|---|---|
| 1 | 作品包内**存在第二个启动脚本** `start_demo_degraded.bat`，且其行尾为 LF | cmd 解析 LF 行尾的批处理会跳错标签、静默退出＝"双击后窗口一闪就没"；该脚本还开在 **9101** 端口，与说明里的 9000 对不上。它是录演示视频用的内部件，10-18 出包时忘了剔除 | 从包内剔除（`DROP_BAT`），打包器对**每一个** `.bat` 无条件转 CRLF 并断言纯 ASCII；审计新增"存在第二个启动脚本即报问题" | 新包内批处理数量 2 → **1** |
| 2 | `start.bat` **最后一行不兜底**：直接跑 uvicorn，服务进程一退出（端口被占、venv 基座失效、启动期报错）cmd 窗口跟着关闭 | 原因被窗口带走，用户只能报"闪退" | 启动前预检 TCP 9000；进程退出后打印 `[EXIT] server process ended, exit code N` 与"如何复制屏幕内容"的指引，并 `pause` | 人为占住 9000 与杀进程两种情况，窗口均留屏（见第四节 T2/T3） |
| 3 | `核验说明.md` 的**通过判据与脚本实际输出漂移**：说明写"看到 `[3/3] 启动服务` 即通过"，而包内脚本早已输出英文 `[n/5]` 步骤行 | 同学照说明永远找不到那一行，只能判"未通过"——**说明越详细，误导越具体** | 出包时从包内 `start.bat` 正则抓出每个 `echo [n/5]` 行，逐条断言"该字符串确实在说明里"，缺一条拒绝出包 | 5 个步骤行全部命中；故意把说明改回旧步骤号会被拒（闸已用样本验过） |
| 4 | `诊断.bat` 跑到第 [9] 节**整个批处理中止** | 该节用 `wmic` 取磁盘剩余；**Windows 11 24H2 起 `wmic.exe` 已被删除**（本机 10.0.26300 实测），而**管道左侧程序缺失会让 cmd 中止整个 .bat**，不是报一行错继续。结果 `diag.txt` 只有 10/13 节，最有价值的 [10]—[12] 从未生成 | 去掉 wmic，改用 PowerShell `[System.IO.DriveInfo]`；同时修掉同轮查出的两条同类坑（见第三节） | 重跑后 13 节全出，磁盘三处数值有实内容 |

## 二、为什么先前两版都没发现

10-18 也做过"端到端跑一遍"，但那次只验了**成功路径**：解压 → 跑起来 → `/api/health` 返回 414。
三条失败路径（误点另一个脚本、端口被占、诊断脚本本身中途死掉）都没测，所以"包能跑"被当成了
"包能交付"。本次把场景拆成 5 条并逐条写判据，才把 #1—#4 全部暴露。

**教训（写进后续交付纪律）**：发给别人的一键脚本，验收必须包含"它失败时会不会把失败原因带走"。

## 三、排查工具自身也错过（如实记录）

给批处理新写的静态检查器（查块内裸括号、同块 `set` + `%引用%`）首版是**空转的**：它用文本模式
读文件，Python 的通用换行把 CRLF 折成 LF，于是按 `\r\n` 切分永远只得到 1 行，两条规则一次都没跑，
却对真实文件报"0 违规"。是拿一份**故意写坏的样本**做正对照、结果同样命中 0 条，才暴露。
改为二进制读并断言"切分行数 > 1"后，样本命中 4 条、真实文件 0 条。

同轮被这条检查器抓出来、并已修掉的写法问题：

- `if (...)` 块内 `set "MI=%TEMP%\x.txt"` 又用 `"%MI%"` 重定向：整块是一次性解析的，`%MI%` 展开为
  空串 → 重定向写成 `> ""` → cmd 报"系统找不到指定的路径"，**并把 8 个已装好的依赖全部误判 FAIL**（假红）。
- `if (...)` 块内放含 `[math]::Round(...)` 括号的 PowerShell 行：第一个未转义 `)` 提前闭合整块。
- `pushd "!ROOT!"` 之后仍用带 `ROOT` 前缀的相对路径调用解释器 → 路径被拼两遍。

## 四、复测矩阵（干净沙箱、无 `.venv`，从零跑）

| 用例 | 场景 | 结果 |
|---|---|---|
| T1 | 全新解压 → `start.bat` 从零建虚拟环境并起服务 | 通过。约 30 s 后 `Uvicorn running on http://127.0.0.1:9000`；`/api/health` = `{"status":"ok","llmConfigured":false,"docs":34,"chunks":414,"hybrid":{"ok":true,"backend":"onnx-int8","n_chunks":414}}`；浏览器取到 `/`、`/style.css`、`/app.js`、`/api/examples`、`/api/roles` 均 200 |
| T2 | 人为占住 9000 端口后再启动 | 通过。命中 `[ERROR] TCP port 9000 is already being listened on`，打印"改 `set "PORT=9010"`"与 Windows 保留端口段提示，停在按键提示不关窗 |
| T3 | 服务运行中终止解释器进程 | 通过。打印 `[EXIT] server process ended, exit code 1` 并留在屏幕，等按键 |
| T4 | 从核验包**外层**目录运行新增的 `run_server_test.bat` | 通过。自动定位到 `jianan-agent`，前台起服务，结束后同样不关窗 |
| T5 | 运行 `诊断.bat` | 通过。13 节全部生成；逐项 import 判定 **17 OK / 0 FAIL**；`.venv runs fine`；`app.main imports cleanly`；`pypi HTTP 200` / 镜像 `HTTP 200`；磁盘与保留端口段均有实际数值 |

即"测过的那份就是发出去的那份"。作品包审计同时通过：身份词 0 处、批处理 CRLF + 纯 ASCII、包内仅 1 个启动脚本。
