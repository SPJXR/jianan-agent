# 技术架构与测试说明

**作品**：面向建筑施工安全领域的可溯源法规条款智能问答系统（建安法规问答助手）
**版本**：v5.2　|　**文档日期**：2026-10-11　|　**代码版本**：见 `git log`
**复现方式**：`python tools/verify_all.py` —— 本文所有"已验证"结论均可由该命令一次性复算，报告自动落地为 `docs/核验报告.md`。

## 一、系统定位

| 项 | 内容 |
|---|---|

## 三、请求全链路

```
用户提问
  │
  ├─ POST /api/chat (SSE) ── 限流：每 IP 20 次/分钟（config.RATE_LIMIT_PER_MIN）
  │
  ├─[1] BM25 检索  retrieval.search()
  │      jieba 分词（含 40+ 领域词加词典）
  │      → FTS5 trigram 短语匹配 + LIKE 双字滑窗扩召回
  │      → 覆盖率重排：score = coverage×2.0 + bm25归一bonus
  │        (+2.0 整句命中 / +0.6 标题命中 / ×时效系数)
  │      → 先按 coverage≥0.2 过滤，再截 top-k
  │
  ├─[2] 两阶段检索改写（弱命中时）
  │      LLM 先把口语表述改写为法规术语（"挖坑底下干活"→"有限空间作业"）再检索
  │
  ├─[3] 混合检索 hybrid_search()（ADR-002，条件补充式）
  │      强命中：完全走 BM25，向量不参与 → 零回归
  │      弱命中：向量 top-5 置前 + BM25 top-N 去重追加
  │      向量路：bge-small int8 ONNX（CPU）+ 24h Redis 式本地缓存
  │      两路均施加时效稳定分区（ADR-006）
  │
  ├─[4] 引用契约构建 main._sources_payload()
  │      {no, docId, chunkId, title, category, clause, pages,
  │       validStatus, excerpt(≤220字逐字), full(逐字全文)}
  │
  ├─[5] 生成 llm.stream_chat()
  │      OpenAI 兼容接口，首 token 60s / 总 120s 超时
  │      5 套角色化提示词（ADR-003），6 条契约规则逐字保留
  │
  └─ SSE 事件流：status(retrieving) → status(retrieved) → sources
                → delta(逐字增量) → done | error | notice
```

**降级分支**（任一条件触发即走，不中断服务）：

| 触发条件 | 行为 |
|---|---|
| 未配置 API Key | 提示条说明 + 直接展示检索命中的**条款原文**（逐字） |
| LLM 401/429/超时/网络错误 | 分类文案提示（不暴露技术细节）+ 降级为检索展示 + 重新生成按钮 |
| `HYBRID=0` 或模型/索引加载失败 | 秒级回退 BM25 单路 |
| 检索相关度 < `MIN_COVERAGE`(0.25) | 明确回答"知识库中未找到与该问题直接相关的条款" |
| 相关度处于弱相关区间 | 警示 + 仅给字面相似片段并标注"请勿作为依据" |
| 非法角色参数 | 自动回退 `default`，不改变任何契约规则 |

## 四、技术选型与取舍（每条都有实验或约束依据）

| 决策 | 选择 | 理由与证据 |
|---|---|---|
| 检索主干 | **SQLite FTS5 + BM25 + 覆盖率重排**，而非向量库 | 条款查询是精确字面匹配主导的场景；414 片段规模下 FTS5 单文件、零运维、CPU 毫秒级。向量单路实测 top-3 100% 但整体不优于调优后的 BM25（`docs/research/POC-混合检索对比.md`） |
| 混合策略 | **条件补充**，而非论文常用的 RRF 融合 | 实测 RRF 使 top-3 从 **71.4% 降到 64.3%**；加权网格扫描 VEC_W 0~8 **全部 64.3%**，根因是 BM25 已调优的全序被均匀融合"平均"掉。**该结论偏离所参考论文的 RRF 思路，偏离理由与数据写入 ADR-002** |
| 向量兜底阈值 | **不采用** | 库内/库外相似度分布重叠（0.493~0.605），不存在可靠阈值；兜底判据维持覆盖率口径（POC 报告 §3.1） |
| Embedding 模型 | **bge-small 优于 bge-large** | 小语料垂直场景下 large 反而劣化；且服务器无 GPU |
| 推理形态 | **ONNX Runtime int8 量化，CPU 执行** | 模型 92 MB → **23 MB**，适配 2 vCPU / 2 GiB 无 GPU 的云服务器 |
| 前端 | **原生 JS，无框架无构建** | 部署即静态文件；评审/队员拿到就能改；避免 node_modules 进入交付物 |
| 分块策略 | **表格感知分块 + 语义锚点**（ADR-005） | 法规文本大量表格，按行切会丢语义；给表格块挂"文档标题/类别/章节"锚点并计入覆盖率，把"对的文档、错的块"从 15~30 位拉回窗口。片段数由 422 调整为 **414** |
| 埋点 | **自建端点，只存事件名计数**（ADR-001） | 第三方统计引入数据出境与合规成本，与"本地知识库、可信"定位冲突 |

## 五、知识库数据流水线

```
knowledge_base/docs/  34 份原始文档（.doc/.docx/.pdf，含扫描件）
   │ tools/extract_docs.py   .doc → Word COM 转 docx；.docx/.pdf 解析
   │ tools/ocr_scans.py + ocr_image.ps1   扫描件走 Windows.Media.Ocr 中文 OCR
   ▼
kb/text/<doc_id>.txt  抽取纯文本（引用溯源的唯一数据源）
   │ tools/build_kb.py   条款感知 + 表格感知分块 → FTS5 索引 + 语义锚点
   │                     读取 kb/docs_meta.json 写入 docs 表
   ▼
kb/kb.sqlite          docs(34) + chunks(414) + chunks_fts
   │ tools/build_vec_index.py / quantize_bge_small.py
   ▼

```

**时效元数据**：`kb/docs_meta.json` 的 `valid_status` / `version_date` 经 `tools/backfill_validity.py` 核定写入，逐条依据与来源见 `docs/法规时效核查台账.md`。当前 **23/34 已核定**（`effective` 5、`trial` 4、`consultation` 1、`na` 13），**11 份仍为 `unknown`**，界面如实显示"时效待确认"。

## 六、引用逐字契约（本系统的信任基础）

**性质定义**：系统展示的每个引用片段，均为知识库源文本经排版归一化（**仅折叠空白与分页标记差异，不改写、不增删任何字符**）后的**连续原文子串**。

**校验方式**：`python tools/verify_verbatim.py`（纯标准库，可重跑）

| 项 | 实测值（2026-10-11） |
|---|---|
| 片段总数 | 414 |
| 逐字命中 | **414** |
| 不一致 | **0** |
| 其中完全原样子串 | 201 |
| 其中折叠空白后命中 | 213 |
| 索引基线哈希 | `SHA-256(chunk_id,doc_id,seq,clause,pages,text)` = `2e65efd1315806ff…` |

**为什么必须交代"折叠空白"**：51%（213/414）的片段是在折叠空白后才与源文本对齐的。只说"逐字一致"而不说口径，被追问时守不住；说清口径反而是更强的证据。

**时效降权（ADR-006）**：`consultation`×0.15、`repealed`×0.35；`trial`（试行·已施行）、`na`、`unknown`、`effective` **一律不降权**。修复实例：问题"有限空间作业前需要检测哪些气体"修复前首条引用为 **0070 征求意见稿**，修复后 top-5 全部为 **0069 试行版**。

## 七、安全与隐私设计

| 项 | 实现 | 对应验证 |
|---|---|---|
| API Key 不外泄 | 仅存服务端 `.env`，不进前端代码与网络请求；`.env` 已入 `.gitignore` | 人工核验 + `git ls-files` |
| 防刷 | 每 IP 20 次/分钟（提问）、埋点 60 次/分钟 | iter2 用例 |
| 埋点最小化 | **只存「日期+事件名+计数」三元组**，不存问题原文、不存用户身份、不存 IP 明文、不存属性明细；事件名白名单正则 `^[a-z][a-z0-9_]{2,39}$` | `track_stats_auth_test` 断言"上报带 question 后，统计响应中不含该原文" |
| 统计端点鉴权 | 配置 `TRACK_STATS_TOKEN` 则校验（常数时间比较，支持 query 与请求头）；未配置则**仅放行本机回环**，公网 403 | `tests/track_stats_auth_test.py` 7 个用例 |
| 人工复核机制 | 6 条契约规则（逐字引用、诚实拒答等）在 5 套角色模板中**逐字保留并做逐句断言回归**；AI 生成内容不得直接作为依据，界面固定免责文案 | `iter5_role_test` 15 项 |
| 错误信息最小化 | LLM 错误分类文案（鉴权/限流/超时/网络），不暴露堆栈与技术细节 | `iter2_api_test` |
| 反馈数据本地化 | 回答反馈存浏览器 `jz_feedback_v1`，用户可自行导出 JSON，服务端不留存 | `iter2_smoke` F8 系列 |

## 十、已知边界（不掩饰）

1. **11 份文档时效状态未核定**，界面显示"时效待确认"。宁可显式承认未核，也不给未经验证的"现行有效"。
2. **评测金标准由项目方自行标注**（依据条款原文），未经独立第三方复核；因此上表反映的是"与自定预期的一致性"，不等于专家认定的正确率。专家抽检见《试用数据采集规程》D 项。
3. **评测集 62 题规模有限**，单项 1~2 题的差异不具统计显著性；本文只报原始计数，不做百分比包装。
4. **端到端延迟依赖外部 LLM 服务**（中位 1.94 s）；未配置 Key 时降级为检索展示，延迟只剩检索的毫秒级。
5. **埋点不存身份**，因此无法计算用户级漏斗与留存；这是 ADR-001 的刻意取舍，不为统计便利而改变。
6. **公网实例可达性本次未验证**（核验环境网络受限），对应检查记为 SKIPPED。
7. **OCR 文档存在识别噪声**：0003/0004/0067 为扫描件，0004 仅少量文字可检索，0002 为空表格模板（故 34 份登记、32 份产出片段）。
8. **0063 与 0064 是同一部规章的两种版式副本**，会在引用中重复出现同一内容，属语料去重待办项。
