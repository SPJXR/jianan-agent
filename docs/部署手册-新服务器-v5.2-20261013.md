# 部署手册 — 新服务器全量部署 v5.2（表格感知分块版）

> 编写日期：2026-10-13
> 适用：更换后的全新 Windows Server（阿里云），从零部署 jianan-app-v5.2
> 部署包：`D:\wdagent\2026-09-19-17-37-04\deploy-pkg\jianan-app-v5.2.tar.gz`（15.9MB，自包含：代码 + kb 414 块 + 双向量索引 + bge 模型）
> 文中 `<新服务器IP>` 替换为实际公网 IP；服务器用户以 `Administrator` 为例

## 阶段 A：本机上传（2 条指令，本机 Git Bash / PowerShell 均可）

```bash
# A1. 上传部署包到服务器
scp "D:/wdagent/2026-09-19-17-37-04/deploy-pkg/jianan-app-v5.2.tar.gz" Administrator@<新服务器IP>:"C:/Users/Administrator/"

# A2. 单独上传 .env（含 API Key，勿打进包里）
scp "D:/wdagent/2026-09-19-17-37-04/deploy-pkg/env-上传服务器时单独用.txt" Administrator@<新服务器IP>:"C:/Users/Administrator/"
```

若本机无 scp/密钥未配置，可用阿里云 Workbench 的「上传文件」，或 WinSCP 图形化拖拽，效果相同。

## 阶段 B：服务器基础环境（远程桌面 / Workbench 登录后，管理员 PowerShell）

```powershell
# B1. 安装 Python 3.13（若服务器已有 python 3.12+ 可跳过；python --version 验证）
winget install Python.Python.3.13
# winget 不可用时：浏览器下载 https://www.python.org/downloads/ 安装包，勾选 "Add python.exe to PATH"

# B2. 安装 VC++ 2019 运行时（onnxruntime DLL 依赖，Windows Server 默认不带——v4 部署实测踩过的坑）
#     浏览器下载 https://aka.ms/vs/17/release/vc_redist.x64.exe 后执行安装
cd $env:TEMP; curl.exe -LO https://aka.ms/vs/17/release/vc_redist.x64.exe; .\vc_redist.x64.exe /install /quiet /norestart
```

## 阶段 C：解压与配置（管理员 PowerShell）

```powershell
# C1. 建目录并解压（--strip-components=1 去掉包内顶层 jianan-app/ 目录，直接落进 C:\jianan）
#     ⚠ 此参数必须带：上次部署曾因解压出 C:\jianan\jianan-app\ 嵌套导致服务仍跑旧代码
mkdir C:\jianan -Force
tar -xzf C:\Users\Administrator\jianan-app-v5.2.tar.gz -C C:\jianan --strip-components=1

# C2. 验证关键文件就位（应有输出，缺一不可）
dir C:\jianan\app\main.py, C:\jianan\kb\kb.sqlite, C:\jianan\kb\vec_index_bge-small-zh-v1.5.npz, C:\jianan\models\bge-small-zh-v1.5\model_int8.onnx

# C3. 放置 .env（上传的 env 文件改名到应用根目录）
move C:\Users\Administrator\env-上传服务器时单独用.txt C:\jianan\.env

# C4. 检查端口 9000 未被系统保留（有输出命中 8939-9038 段则换端口并同步改安全组）
netsh interface ipv4 show excludedportrange protocol=tcp | findstr "9000"
```

## 阶段 D：虚拟环境与依赖

```powershell
# D1. 创建虚拟环境
python -m venv C:\jianan\.venv

# D2. 安装依赖（用清华镜像加速；requirements 已含 onnxruntime/transformers/numpy——v4 因漏列踩过的坑已修复）
C:\jianan\.venv\Scripts\python.exe -m pip install -r C:\jianan\requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

说明：包内已自带 `kb\kb.sqlite`（414 块新库）与向量索引，**不需要**跑 extract_docs / build_kb / build_vec_index；`start.bat` 里的自动构建逻辑不会触发（文件已存在）。

## 阶段 E：启动与验收

```powershell
# E1. 前台试启动（先手动验证，绑定 0.0.0.0 才能公网访问——.env 里 APP_HOST=127.0.0.1 仅对本机生效）
cd C:\jianan
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 9000
```

## 阶段 F：开机自启（关闭前台窗口后服务不丢）

```powershell
# F1. 写服务器启动脚本（与 E1 同命令）
Set-Content -Path C:\jianan\start-server.bat -Value "@echo off`r`ncd /d C:\jianan`r`n.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 9000 >> C:\jianan\server.log 2>&1" -Encoding ASCII

# F2. 注册开机计划任务（SYSTEM 身份，无需登录即启动）
schtasks /Create /TN "jianan-app" /TR "C:\jianan\start-server.bat" /SC ONSTART /RU SYSTEM /RL HIGHEST /F

# F3. 立即用计划任务拉起服务并验证（先 Ctrl+C 停掉 E1 的前台进程）
schtasks /Run /TN "jianan-app"
curl.exe http://127.0.0.1:9000/health
```

## 已知坑速查（历次部署实录）

| 坑 | 现象 | 处置 |
|----|------|------|
| tar 解压嵌套 | 服务跑旧代码/找不到文件 | C1 的 `--strip-components=1` 必须带，解压后按 C2 验证 |
| VC++ 运行时缺失 | onnxruntime DLL 加载失败、混合检索降级 | B2 预装；降级可查 /health 的 hybrid 字段 |
| transformers 漏列 | 向量路起不来 | 已在 requirements.txt，D2 一次装齐 |
| 端口落在系统保留段 | uvicorn 绑定报 winerror 10013 | C4 检查；命中则换 9100 并同步改安全组/防火墙 |
| deepseek 429 | 评测丢题、空响应 | E6 的 `--sleep 3` 必须带 |
| 绑定 127.0.0.1 | 本机能通公网不通 | 必须 `--host 0.0.0.0`（E1/F1） |

## 回滚预案

- 部署前包内旧库无需备份（新服务器首装）；如需回退版本，历史包在本机 `D:\wdagent\2026-09-19-17-37-04\deploy-pkg\`（v4 / v5-rollback / v5.2）。
- 单独回滚知识库：本地留有 `kb_v51_backup_20260923.sqlite`，替换 `C:\jianan\kb\kb.sqlite` 并重建向量索引后方可回退（v5.2 代码与新库配套，混用会静默错配，非必要不操作）。
